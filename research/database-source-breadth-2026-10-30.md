# Iranian managed database source breadth — 2026-10-30

## Result and scope

Chabokan and Weblines provide substantial additional, publicly priced engine/configuration coverage. ArvanCloud is also assessable using its first-party documentation and the web retrieval transcript even though direct HTTP downloads return an interstitial. ManageIT publishes real database tariffs, but its engine-to-plan applicability needs a more explicit source before multiplying its six rows across six engines. Darmant has one clearly engine-specific entry-level offer with incomplete resource detail. SakooCloud prices shared platform quotas, which must not become invented per-database allocations.

This is an acquisition research handoff, not catalog data or synthetic fixtures. No catalog, application or test file was edited; no account was created, provider contacted, purchase made or commit created. Liara inspection is assigned to the parent. All match discussion below is provisional against the familiar Liara size vectors; the parent must reconcile current Liara engine, units, storage and topology evidence.

## Evidence and reproducibility

Evidence root: [`evidence/database-breadth-2026-10-30/`](evidence/database-breadth-2026-10-30/). `manifest.json` indexes every retained artifact with SHA-256 and file timestamp. `capture.py` records direct GETs, raw response bodies, response headers, extracted visible text, outgoing links and a per-request `.meta.json` containing requested/final URL, UTC attempt time, HTTP status, curl exit/error, byte count and raw-body SHA-256. The `.html` extension is also used for actual JSON/API/JavaScript responses; inspect content, not the extension. `.txt`/`.links.json` are derived aids, not substitute originals. `chabokan-flight-decoded.txt` is a decoded derivative of a retained product page.

Search and web retrieval transcripts are retained as JSON. Their transport is `web.run`; where the tool does not expose HTTP status, status is unknown. A web search snippet is a discovery lead, not a freshly downloaded tariff. Several JSON files have a retention timestamp rather than the exact original tool-call time; the transcript and file times delimit the observation, and this distinction is retained. Direct curl observations have exact request timestamps. Empty bodies and interstitials are **failed content verification**, even when HTTP status is 200. No fabricated successful HTTP status or checked date is attached to an inaccessible page.

Important access distinctions:

- Arvan's direct `www.arvancloud.ir` downloads returned HTTP 200 with “Transferring to website,” not the requested tariff; docs curl attempts hit redirect limits. The earlier working note describing this as a 403 was incorrect. Successful first-party textual retrieval is retained separately in `arvan-web.json`, `arvan-header.json`, `arvan-db-docs.json`, `arvan-detail-docs.json`, `arvan-backup.json` and `arvan-docs.json`.
- AbrClick failed DNS resolution from this environment. SkyCloud timed out. Neither failure proves withdrawal or absence of offers.
- Public quote endpoints were read with GET only. A quote response does not prove account-level order availability, capacity, minimum runnable engine memory or unrestricted acceptance of arbitrary input.
